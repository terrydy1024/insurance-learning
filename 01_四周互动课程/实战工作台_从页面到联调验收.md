# 实战工作台：从保险页面走到产品库需求与验收

> 本工作台服务于四周课程第 1、3、4 周。先独立填写空白格，再对照示例。下文的产品事实来自所列公开页面与资料；字段名、后台结构、试算输入和故障处理为教学推演。你在深蓝保的具体动作仍需用项目材料或回忆核对。

## 1. 一次完整拆解先走哪条路

拿到一款保险产品，按下面八步走。不要先画数据库表。每一步都要留下能被别人复核的资料。

| 步骤 | 要回答的问题 | 留下的证据或产物 |
| :--- | :--- | :--- |
| 1. 认主体 | 谁承保，谁销售，谁可能成为投保人和被保险人 | 页面截图或链接、资料访问日期 |
| 2. 认正式资料 | 销售名对应哪份条款和投保须知 | 名称映射卡与条款链接 |
| 3. 认方案 | 页面列出了哪些保障期间、交费期间、保额和责任选择 | 可选项清单、组合限制、未知项 |
| 4. 认责任 | 什么事件触发什么给付，哪些责任必选或可选 | 责任卡与条款章节 |
| 5. 认规则 | 年龄、职业、保额、期间和组合怎样限制申请 | 决策表及边界样例 |
| 6. 认价格 | 哪些输入决定报价，由谁计算 | 报价输入清单、权威参考值来源 |
| 7. 认版本 | 本次展示与试算适用哪套资料 | 生效时间、渠道、资料版本或追踪标识 |
| 8. 认下游 | 页面、计划书、投保、保单服务分别消费什么 | 数据流与回归清单 |

### 为什么要这样排

例如一个页面写“45 岁前额外赔”。直接建一列 `extra_pay=true` 会遗漏责任条件、年龄计算时点、可选方案、费率变化和条款依据。沿八步追溯后，PM 才能写出可供研发实现、测试验收的需求。

## 2. 用定海柱8号做一遍

案例资料：[销售页面](https://www.huize.com/apps/cps/index/product/detail?DProtectPlanId=108801&prodId=104154&planId=108801)；[正式条款](https://files2.huizecdn.com/file3/M00/D6/5F/rBYA3GnKUXqAdLVQAAU4BAbXNV8711.pdf)。公开资料可能更新。复习时记录访问日期，再核对当时页面。

### 2.1 产品身份卡

| 项目 | 当前案例可确认内容 | PM 应怎样使用 |
| :--- | :--- | :--- |
| 销售名称 | 定海柱8号定期寿险（互联网） | 展示与搜索 |
| 正式产品名称 | 国富人寿齐家骏达2026定期寿险（互联网） | 正式资料关联 |
| 承保机构 | 国富人寿保险股份有限公司 | 合同主体与服务信息 |
| 销售机构 | 慧择保险经纪有限公司 | 销售页面与渠道归属 |
| 页面可选内容 | 保障期间、交费期间、基本保额、部分可选责任 | 先从用户看到的选择拆解方案 |

**先读页面的投保须知，再核对当前可操作的选项。**

须知列出的范围如下。实际组合还要按年龄、职业、责任限制和报价结果校验。

| 用户要决定什么 | 页面投保须知列出的范围 | 本课示例选择 |
| :--- | :--- | :--- |
| 保多久 | 10 年、20 年、30 年，或保至 60、65、70 周岁 | 保 20 年 |
| 交多久 | 一次交清、10 年交、20 年交、30 年交，或交至 60、65、70 周岁 | 20 年交 |
| 基本保额 | 最低 10 万元，超过部分按 10 万元递增 | 50 万元 |
| 要不要附加可选责任 | 页面介绍猝死额外赔、特定年龄身故或全残特别关爱金等 | 拟选猝死关爱金 |

示例中的被保险人年龄为 30 岁。这是练习输入。

**具体可售性和保费还需按有效资料及报价服务确认。**

### 2.2 一条责任如何拆成五个产品对象

选择页面提到的特定年龄身故或全残特别关爱金作练习。

| 对象 | 本案例中的含义 | 需要的确认或验收 |
| :--- | :--- | :--- |
| 条款依据 | 正式条款中的可选责任及给付条件 | 保存条款章节、文件版本、资料链接 |
| 责任实例 | 特别关爱金的触发事件与给付比例 | 页面摘要与正式责任相符 |
| 选择规则 | 页面提示 45 周岁及以上不能选择 | 明确年龄计算时点、临界值、清除旧选择的交互 |
| 报价输入 | 当前责任是否选中 | 核对请求中有相应编码，金额由权威来源返回 |
| 投保申请 | 最终提交的保障组合 | 申请前再次校验责任有效性与版本 |

【教学推演】假设用户先以 44 岁选中该责任，再将出生日期改到按业务口径计算为 45 岁。推荐的需求写法：更新年龄后立即重新校验已选责任；若条件不满足，清除或阻止该选项并说明原因；重新报价；最终提交前再次校验。具体交互选择由产品团队确认。验收覆盖 44 岁、45 岁、46 岁，以及修改年龄前后的状态。

### 2.3 从用户选择走到“计划”概念

**第一步，看用户怎样选。**

例如：“30 岁、基本保额 50 万元、保 20 年、20 年交、拟选猝死关爱金。”

这是一份**待校验的投保方案**，包含保额、期间和责任等条件。

**第二步，问产品库怎样组织这些条件。**

有的系统把一组预设组合叫“计划”。有的系统在基础方案上拼接可选责任。

需要看实际平台的资料、报价与投保接口，才能确定这里的计划如何定义。还要核对页面是否真的允许该责任与期间组合。

**第三步，遇到接口排查时再看 URL 标识。**

链接中的 `prodId=104154` 和 `planId=108801` 可用于技术定位当前页面。它们无法说明页面有哪些选择、全部计划有多少个，或者当前计划叫什么。

做用户方案拆解时先看页面和投保须知。排查接口或数据映射时再记录这些标识。

## 3. 用达尔文12号验证方法能否迁移

资料入口：[产品页面](https://cps.qixin18.com/apps/cps/gw1070454/product/detail?prodId=105149&planId=130613&aid=56593e0b-c287-4281-82e2-b3bc081fece6)、[保障责任对照表](https://files2.huizecdn.com/file3/M00/8E/8E/rBYA3GitInGABJt8AADhibPOvn0761.pdf)、[投保年龄上限表](https://files2.huizecdn.com/file3/M00/8E/8E/rBYA3GitInGAB4CfAAFqOUBpZ2s831.pdf)、[投保须知](https://files2.huizecdn.com/file3/M00/DE/B7/rBYA3GngpsmAWypPAAOMokCSsc0614.pdf)。

当前链接可确认页面选中“保终身”，`productId=105149`，`planId=130613`。页面还可切换“保至70岁”。承保公司为复星联合健康保险。销售名称是达尔文12号重大疾病保险，正式主险资料需要关联复星联合优选K重大疾病保险（互联网）相关文件。

完成三项迁移练习：

## 4. 结构化产品库的教学模型

下面是为理解和需求设计而建立的对象模型。它不对应慧择、国富人寿、复星联合、深蓝保或平安的内部数据库。

| 对象 | 最小业务字段示例 | 关键关联 | 消费者 |
| :--- | :--- | :--- | :--- |
| 产品主档 | 销售名、正式名、承保方、产品类别 | 正式资料、版本 | 列表和详情 |
| 正式资料 | 文件类型、来源、适用日期、确认状态 | 产品、责任、规则 | 披露与追溯 |
| 方案或页面计划 | 页面标识、保障期间、允许交费期 | 产品、责任组合 | 详情、报价、投保 |
| 责任 | 触发事件、给付规则、必选或可选、条款引用 | 方案、正式资料 | 页面、计划书、合同说明 |
| 投保规则 | 条件、动作、提示、适用范围 | 方案、版本 | 页面预校验、投保 |
| 价格来源 | 费率文件或报价服务、输入因子、单位、舍入 | 方案、责任、版本 | 试算和报价 |
| 现价与演示 | 年度、领取、现金价值、保证性质 | 年金方案、资料版本 | 试算、计划书、服务 |
| 发布版本 | 适用时间、渠道、状态、审批记录 | 上述对象 | 所有消费端 |

在定寿案例里，现金价值与利益演示对象可能不参与页面试算。在年金案例里，它们常是理解计划书的重点。共用骨架不要求每款产品填写每类字段。

### 一份可以交研发讨论的字段映射表

| 字段 | 用户理解 | 权威来源 | 类型与单位 | 校验与口径 | 状态 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `insured_age` | 被保险人周岁年龄 | 投保须知、接口协议 | 整数，岁 | 按哪个日期计算待确认 | 待确认 |
| `coverage_term` | 保多久 | 页面与正式资料 | 枚举 | 与交费期及责任联动 | 待确认 |
| `selected_benefits` | 买了哪些可选责任 | 责任对照与接口协议 | 编码集合 | 仅传当前方案允许的责任 | 待确认 |
| `premium_amount` | 本次应交保费 | 有效费率或授权报价 | 金额，币种和精度待确认 | 留请求号、版本与时间 | 待确认 |
| `cash_value_year_end` | 指定年末的现金价值 | 年金现金价值资料 | 金额 | 年末时点及领取前后待确认 | 仅年金练习 |

这些编码只是教学字段。实际接口、值域和数据责任人需要在项目中确认。

## 5. 年金试算需求样例

### 5.1 用户故事与边界

【教学模拟】一位顾问为客户比较不同交费期与领取起点，希望在页面完成试算并生成能向客户解释的计划书。PM 先确定用户要回答四个问题：“要交多少”“什么时候开始领”“每期领多少”“中途退出或身故时按什么规则处理”。

本需求样例只覆盖有效资料条件下的试算展示、计划书一致性和错误提示。它不推算具体保费或收益，也不代替保司核保及承保。

### 5.2 输入、处理、输出

| 阶段 | 需要写清楚的内容 | 例子或风险 |
| :--- | :--- | :--- |
| 输入 | 产品与方案、年龄、交费安排、金额、领取方式、渠道 | 年龄的计算日和缴费期组合不清 |
| 校验 | 组合是否允许、资料是否有效、必填是否完整 | 用户切方案后保留了无效领取方式 |
| 计算来源 | 费率资料、保司授权报价、利益资料及版本 | 页面和计划书调用了不同版本 |
| 输出 | 保费、年金领取、现金价值、身故给付及说明 | 金额相同但时间点不同 |
| 留痕 | 输入、结果、版本、时间、请求号 | 无法复现历史试算 |

用户更改年龄、交费期、金额或领取方式后，需求应规定何时重算、旧结果何时失效、错误时如何提示，以及计划书是否必须由当前有效结果生成。

### 5.3 联调记录的完整样例

【教学模拟】样例编号 `S01`，记录一次允许组合。所有金额保留空位，由经确认的权威样例填写。

| 字段 | 待填写内容 |
| :--- | :--- |
| 产品与方案 | 【以实际项目资料填写】 |
| 用户输入 | 年龄【】；交费期【】；领取起点【】；金额【】 |
| 渠道与适用版本 | 【】 |
| 权威参考资料 | 文件名【】；表页【】；确认人【】 |
| 请求证据 | 请求ID【】；时间【】；发送字段【】 |
| 返回结果 | 保费【】；各年领取【】；各年现金价值【】 |
| 页面展示 | 数字【】；单位【】；时间标签【】；保证性质【】 |
| 计划书展示 | 数字【】；单位【】；时间标签【】；保证性质【】 |
| 差异与处理 | 差异【】；定位环节【】；责任人【】；回归结果【】 |

联调顺序：先核对请求输入，再核对计算或资料返回，最后核对页面及计划书展示。若输入已经错误，先修字段映射；若返回错误，核对数据或计算来源；若返回正确且展示错误，查前端或模板。每次都保留同一个样例编号和版本。

### 5.4 验收矩阵

| 类型 | 样例 | 检查点 |
| :--- | :--- | :--- |
| 典型 | 常见年龄与交费期 | 页面、接口、计划书同一输入同一版本 |
| 边界 | 最小和最大年龄及其相邻值 | 禁止条件、选项清除、提示 |
| 边界 | 最短与最长交费期及领取起点 | 组合矩阵与时间口径 |
| 异常 | 缺字段、无效组合、报价超时 | 明确失败状态，不显示虚假的0元结果 |
| 变更 | 旧链接、新试算、在途申请 | 适用版本及重新确认策略 |
| 历史 | 已承保保单 | 以对应合同和后续约定提供服务 |

## 6. 四个故障的排查表

全部是【教学模拟】。你的实际项目是否遇到过，需用第 7 节的回忆题确认。

| 现象 | 先保存什么 | 优先定位 | 协作处理 | 回归 |
| :--- | :--- | :--- | :--- | :--- |
| 保费或现价对不上 | 输入、版本、渠道、请求ID、两端结果 | 费率或现价资料、时间口径、舍入、字段映射 | 产品运营与有权确认者核对来源，研发修实现 | 原样例及相邻年龄、年度 |

## 8. 面试自测

1. 不看资料列出定海柱8号的保障期间、交费期间、保额和可选责任，再画出承保机构、正式条款、规则与报价的关系。
